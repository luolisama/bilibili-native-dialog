# bilibili类原生查看对话

当前脚本版本：`0.5.2`

这是一个最小权限 Tampermonkey 用户脚本：在 B 站原生楼中楼操作栏中，为“回复了另一条回复”的评论添加同风格的“查看对话”。点击后显示一层“对话列表”面板。

## 安装

1. 安装 Tampermonkey 或 Violentmonkey。
2. 打开 `bilibili-native-dialog.user.js`，复制全部内容到用户脚本编辑器并保存。
3. 打开或刷新 B 站视频、动态或专栏页面。

脚本匹配 B 站主域及其子域（`https://*.bilibili.com/*`），并声明 `@grant none`。只读功能不需要填写 API Key；点赞、点踩和回复时只临时读取当前页面可见的 `bili_jct`，不会保存 Cookie。

## 当前实现

- 入口插入原生楼中楼操作栏，文字为“查看对话”，不使用红色。
- 点击后调用 B 站只读评论对话接口 `/x/v2/reply/dialog/cursor`。
- 使用 `root`、`dialog`、`rpid` 字段识别对话关系，并按游标顺序分页。
- 对话项使用接近 B 站评论区的结构：头像、个人空间链接、LV0-LV6 等级徽标、表情渲染、IP 属地和时间。
- 点赞、点踩调用 B 站评论操作接口，成功后立即更新当前项状态和点赞数。
- “回复”会打开面板底部输入框，使用 B 站回复接口发送，并在成功后重新拉取对话列表。
- 输入框增加接近 B 站原生评论框的表情按钮：首次打开时按需请求 `/x/emote/user/panel/web?business=reply`，点击表情会插入 B 站可识别的 `[表情名]` 文本。
- 表情面板在弹窗内部左右收束，分类标签横向滚动，表情网格独立纵向滚动，避免选项越过对话窗口边界。
- 输入框增加原生风格的 `@` 按钮；点击后或直接输入 `@` 会显示“选择或输入你想@的人”，按“最近联系 / 我的关注”分组展示，并在继续输入关键词时调用带 WBI 签名的网页用户搜索，旧搜索接口只作为回退。选中用户后会插入 `@用户名 `，发送时同时提交 `at_name_to_mid` 映射，避免只发送普通文本。
- 点踩按钮保持 B 站评论区的图标样式，只保留可访问性标签，不在图标后显示“点踩”文字。
- 对话面板支持遮罩关闭、`Esc` 关闭、移动端底部抽屉布局、浅色/深色主题。
- 只在点击时请求，并按评论组合键做短期内存缓存。
- 评论对象按页面实际返回的 `type + oid` 处理，兼容视频（1）、图片动态（11）、专栏（12）和文字/转发动态（17）；无法从页面地址推断时，以评论对象自身字段为准。

点赞、点踩和回复属于登录态写操作：脚本只从当前页面读取 `bili_jct`，不会保存 Cookie；未登录、评论区关闭、风控或 CSRF 不可用时会在面板中提示错误。

## 兼容边界

脚本不替换评论组件、不改写全局 `fetch`、不劫持 B 站现有按钮，目标是与保留原生 `bili-comments` 的增强脚本共存。表情请求也只在打开表情面板时发起。

这里的“复用 B 站原本实现”采用的是接口层复用：对话、表情、用户资料、@ 映射和发送参数都沿用 B 站网页协议；弹窗编辑器本身不直接克隆 B 站评论组件的 DOM。B 站评论区使用私有 Shadow DOM，内部输入组件和事件不是稳定的公开 API，直接搬节点会在 B 站更新或与其它脚本同时运行时失效，所以脚本保留隔离的编辑器作为稳定壳层。

`@` 面板的“最近联系”使用当前对话中已返回的用户作为稳定的网页端回退，“我的关注”通过当前登录态的关注列表补充；关键词搜索使用网页用户搜索接口，搜索被风控或失败时回退到这两组本地候选。B 站移动端还存在 gRPC `AtSearch`，但它不是浏览器用户脚本适合直接依赖的接口，因此没有把 protobuf/gRPC 客户端塞进脚本。

表情面板没有直接复制 B 站评论组件的 Shadow DOM。脚本复用 B 站表情接口和表情转义文本，面板结构保持自己的命名空间和生命周期；这样不会绑定 B 站私有组件的内部节点。若要逐像素复刻 B 站表情面板，需要继续单独调整 CSS/布局，而不是简单克隆现有 DOM。

脚本仅使用带命名空间的 `bdv-*` CSS 类。若同时启用会整体替换评论组件的旧版页面/翻页脚本，原生评论对象可能不可见，入口会优雅地不显示；建议不要同时启用两套评论区改版脚本。

当前版本优先支持上述四类常见评论区；其他 B 站页面若评论组件返回标准 `type + oid` 字段，也会尝试工作。直播、私信、搜索结果等没有标准评论组件的页面不会强行插入入口。
